What we are building

Every module declared in .hd. The world comes in on the left and goes out on the right; nothing in the middle touches it. Click any function to follow the path through it — everything it reaches and everything that reaches it. Click the background to clear.

Legend
Columns

input I/O — reads the world

orchestrators — own the sequence

pure core — no I/O, laid out in call depth, callers left

output I/O — writes the world

Lines

declared chain — the pipeline, input to output

invokes — one function calls another

dispatch — a table picks the handler; the label carries the table and, after ·, the field the handler is fed

data — one function's answer is the next one's argument, derived from the types when both are called by the same function. The label names the type handed over.

return — the answer going back to whoever called. This is the one line that runs right to left, and it may, because the arrowhead says which way it goes rather than the position of the cards. Each card also names its receiver in words, so it reads without clicking.

A line takes the colour of the column it leaves. A call leaves a right edge and arrives at a left edge; a return does the reverse. A line that would cross a card runs over the top of the board instead.

Red means one thing

a broken rule, never a role and never decoration. A red card names the rule under its signature; a red dashed line is an edge that must not exist.

Clicking

A function lights its path, outlines itself as you are here, and marks the types it consumes above: solid for what its signature names, faint for what it only reaches through them.

A type lights every function that touches it, with no lines, because a type has no direction.
