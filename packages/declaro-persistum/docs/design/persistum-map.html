What we are building

Every module declared in .hd. The world comes in on the left and goes out on the right; nothing in the middle touches it. Click any function to follow the path through it — everything it reaches and everything that reaches it. Click the background to clear.

Legend
Columns

When a module declares its surface, its inputs and outputs, the boundary columns are sectioned by side: a door or reader sits under the side of the world it reads, an output boundary under the side it writes, and a boundary off the list stands under a red no declared side.

input I/O — reads the world. A door is where the world calls in, and nothing inside calls a door; a card marked ⇤ pull is a read the program asks for, a clock or a file it chose to open, which an orchestrator calls and which calls nothing

orchestrators — own the sequence

pure core — no I/O, laid out in call depth, callers left

output I/O — writes the world

Lines

An arrowhead is a call: control goes where it points. A hollow circle is data: a value goes there and control does not.

declared chain — the pipeline, input to output

invokes — one function calls another; its pill says calls

dispatch — a call too, but a table picks the handler; the label carries the table and, after ·, the field the handler is fed

data — not a call. One function's answer is the next one's argument, derived from the types when both are called by the same function; the value travels through that caller. The label names the type handed over.

return — its pill says returns; the answer going back to whoever called. This is the one line that runs right to left, and it may, because the arrowhead says which way it goes rather than the position of the cards. Each card also names its receiver in words, so it reads without clicking.

A line takes the colour of the column it leaves. On every card a line comes in on the left and leaves on the right, except an orchestrator, where lines come in on the top, out of the corridor above the row, and leave on the bottom, into the bus below it. A line that must reach the top of an orchestrator from below goes around the end of the row.

Red means one thing

a broken rule, never a role and never decoration. A red card names the rule under its signature; a red dashed line is an edge that must not exist.

Clicking

A line, or its pill, can be clicked too: it lights up bright and every other line dims, until you click it again, another line, or the background.

The typed dicts are hidden at rest. A function lights its path, outlines itself as you are here, shows the dispatch tables it owns as tables (each key and the handler it picks), and brings out the types its signature names, with their fields open; what it only reaches through those stays hidden.

An italic line on a card is the declaration's note, the one comment the file keeps; a # comment never reaches the map. The triangle on a card folds it to its name and opens it again; every card opens on load. While a function is picked, the cards on its path gather at the top of their layer; while a type or an environment variable is picked, the functions that use it do the same; clearing puts every card back. Cards sort by name within a column, and you may drag one to a new place within its layer; this browser remembers the order, the file never does, and the declared order button puts it back.

A type lights every function that touches it, with no lines, because a type has no direction, and opens what it is made of: a typed dict its fields, a set its values, a vocabulary its sets, an alias what it stands for. A declared type name is bold wherever it is written and a plain word is a primitive; in the signature of the function you have selected it is underlined and clicking it opens that type; in the fields of a type it is underlined and clicking it unfolds that type in place, its fields indented under the one that named it, as deep as you keep clicking, and a second click folds it back. On any other card a click on the name picks the function. handle is a value held and passed to a boundary, never read, a driver connection or a file; a pure function that names one in its signature is red. any means nobody has decided this type yet. A card whose answer can be a Fault wears can fault, and every caller of one must wear it too, because a fault travels by return and nothing else; a caller that cannot return the fault its callee can is red. A card the caller must await wears awaited, and every caller of one must wear it too, along the same edges; a caller left unmarked is red. An environment variable, in the box above the types, lights the input boundary that reads it, and it is red when nothing does. A store, in the box beside it, is what the module holds between calls: one pure function's answers by its arguments, with the reason it exists; it lights the orchestrator that keeps it, the held function wears held in its name, and a store nothing keeps is red.
